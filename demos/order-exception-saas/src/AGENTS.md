# 出荷例外画面の開発指示

rootと親ディレクトリの`AGENTS.md`、`demos/maf-magentic-scrum/skills/frontend-design/SKILL.md`、`docs/frontend-design.md`に従う。

- 受注を画面の主対象にする。現在の段階、次に動く担当者、その画面で行う操作を先に示す。
- 顧客回答と出荷責任者の承認を別の操作として扱う。Agentの対処案だけで引当や出荷指示を確定しない。
- 固定した合成対処案は`fixed_fixture`と表示する。AI生成、ログイン認証、OpenFGA判定がない段階では成果として表示しない。
- Agent runは保存済み履歴を一定間隔で読み直す。ライブtoken配信やAG-UI接続と呼ばない。Managerの担当選択、Tool資料読取り、失敗、完了をrun IDと結び、Agent内の案提出イベントを業務APIの完成案と区別する。
- 実モデルのrunと試験ランナーのrunを`executionMode`で分ける。runの`completed`は業務上の妥当性や出荷承認を意味しない。AIの案を固定案の承認入力へ自動投入しない。
- MUIの業務画面を使い、白いヘッダーとパネル、薄いグレーの主面、濃紺の文字、日本語で読める書体を維持する。根拠資料は開閉できる補足に置く。
- 更新操作では受注版と操作IDをAPIへ送る。同じ入力の通信再試行では同じ操作IDを使い、競合時は最新状態を読めるようにする。
- 1440pxと390pxの実ブラウザーで回答、承認、引当結果の再読込、無効状態、横はみ出し、JavaScript例外を確認する。
